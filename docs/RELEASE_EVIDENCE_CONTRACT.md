# Release evidence contract

This additive tooling does not approve a release, replace A–K, or run customer
workflows. It prevents silent omission and stale/mismatched evidence references.
Keep the unredacted private source/data archives separate from customer output.
Only privacy-reviewed evidence belongs in a distributable support/release bundle.

Run `node scripts/verify-release-evidence.mjs <manifest.json> <40-character SHA>`.
Manifest format1 requires `commit` and exactly11 `gates` (IDs A through K).
Each gate needs a factual `note`, `status` and `evidence` array. Allowed statuses:
PASS, WARN, FAIL, SKIPPED, NOT VERIFIED. PASS needs at least one reference with
`path` (under evidence/) and lowercase SHA256. Missing files, links in ancestors,
path escapes, digest mismatch, duplicate/unknown gates and oversized inputs fail.
Every non-PASS gate keeps the CLI exit nonzero, including SKIPPED and WARN.
Even when all submitted references match, acceptance remains NOT VERIFIED:
hashes prove bytes, not truth, successful execution, environment or relevance.

Evidence owner must separately bind each execution to exact source commit,
runtime/package build, command, time, environment, result and reviewer. Do not
use screenshots of a different build or API checks as proof of rendered behavior.
K's final recommendation is a human evidence-backed document, not generated by
this checker. No archive, package, signing, updater, database or live app state is
modified by verification. Failed checks do not rewrite evidence.

Clean Windows gate G requires an exact frozen package on a clean target without
Node/npm/Git/IDE/dev vars, plus install/first start/config/import/research/export/
restart/update/health acceptance/recovery/repair/uninstall policy. Record actual
OS, package SHA256, signer, channel, storage policy, before/after build/schema,
and safe screenshots/traces. Docker and the developer laptop are not substitutes.
No clean target or trusted signing service is currently demonstrated.

Final artifacts remain source-archive/, private-data-backup/ and release/ with
separate access controls. Final customer distribution must be compiled/runtime
only and self-contained. Existing Node/npm-dependent ZIP is not that artifact.

Focused test uses only synthetic data, no providers or production files. Passing
the test proves checker behavior, not a single real release acceptance gate.
